# Security Policy

## Supported Versions

We release security updates and bug fixes for the current major release track.

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

If you discover a potential security vulnerability in pysentra, please report it responsibly and privately. Do **not** disclose security vulnerabilities through public GitHub issues, pull requests, or public discussions.

### Preferred Reporting Method

1. **GitHub Private Security Advisory (Recommended)**:
   Navigate to the [PySentra Security Advisories](https://github.com/Sanjiv215/PySentra/security/advisories/new) page on GitHub and click **"Report a vulnerability"**. This allows secure, encrypted, collaborative handling of the advisory before publication.

2. **Security Contact Email**:
   If you cannot use GitHub Security Advisories, send an encrypted or direct email to:
   - **Contact**: `sanjivprasad360@gmail.com`
   - **Subject**: `[SECURITY] Potential vulnerability in pysentra`

### What to Include

Please provide:
- A clear description of the vulnerability and potential attack scenarios.
- Reproduction steps or minimal proof-of-concept (PoC) demonstration.
- The pysentra version(s) affected.
- Any potential remediations or patches you suggest.

## Expected Response Time

- **Initial Acknowledgment**: Within 48 hours of receipt.
- **Triage and Assessment**: Within 5 business days.
- **Fix and Release**: Critical vulnerabilities are prioritized for immediate remediation and a point-release update.
- **Coordination**: We will coordinate the public disclosure date with the reporter.

## Ethical and Safe Research

pysentra is designed exclusively for authorized assessments. Security researchers analyzing pysentra must ensure their testing does not violate laws or endanger target systems.
